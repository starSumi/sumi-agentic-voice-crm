# P4 — CRM safety and persistence

**Status:** in progress; the reference store demonstrates command, idempotency,
review, audit, and outbox semantics. The migration now has repeatable PostgreSQL
transaction and two-tenant RLS evidence, while the durable runtime adapter,
review decision persistence, and production operations remain open under C2.

**Owner:** crm-owner + data-owner + security-owner
**Purpose:** make CRM aggregates authoritative and prevent model output from
directly mutating business state.

**Outputs:** command handlers, RBAC/policy checks, optimistic versions,
idempotency records, review queue, PostgreSQL migrations/RLS, audit records and
transactional outbox.

**Exit criteria:** C2 is re-verified against a real database; cross-tenant
queries fail closed, retries cannot duplicate, conflicts are explicit, and
audit/outbox commit atomically with the business mutation.

**Rollback:** application rollback first; use expand/migrate/contract for schema;
never destructive database rollback of committed business data.
