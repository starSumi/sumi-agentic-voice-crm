# P2 — domain and contract hardening

**Owner:** contract-owner + domain-owner + data-owner
**Purpose:** convert architecture into versioned, machine-checkable HTTP, event,
command, error, review and database contracts.

**Outputs:** OpenAPI, event registry/envelopes, JSON schemas, Postman examples,
SQL migrations, invariants, compatibility/deprecation policy and traceability.

**Exit criteria:** C1 and C2 evidence pass; schemas parse, text/audio variants
agree with runtime, tenant/idempotency/error semantics are explicit, and every
mutation has a transaction/audit/outbox design.

**Rollback:** additive contract release or versioned migration; breaking changes
require a new major contract and compatibility window.
