# C2 — domain safety

**Status:** in progress. `pnpm run test:postgres` now proves the migration,
two-tenant `FORCE RLS`, CRM/command/audit/outbox commit and rollback, durable
TTS asset replay/conflict, tenant-scoped asset lookup, and review decision
idempotency on an isolated PostgreSQL cluster. The gate remains open until a
seeded HTTP PostgreSQL deployment is exercised end to end and independent
approvers attach evidence for identity, interaction persistence, policy
validation, recovery, and retention.

**Gate owner:** crm-owner
**Approvers:** data-owner, security-owner, reviewer

## Checklist

- [ ] Every command carries tenant, actor, policy and idempotency context.
- [ ] Model output is untrusted and schema/policy/entity validated.
- [ ] Mutations use transaction + optimistic version + unique idempotency record.
- [ ] Low confidence and high risk actions create durable review tasks.
- [ ] Audit record and outbox event are atomic with the CRM mutation.
- [x] Migration reapplication, two-tenant RLS, and atomic commit/rollback are tested on PostgreSQL.
- [ ] Runtime command handlers use the durable store instead of the reference-memory store.
- [ ] Remaining FKs/indexes, review decision lifecycle, and retention jobs are tested.

## Required evidence

Database migration smoke, two-tenant matrix, duplicate/conflict tests, audit and
outbox round-trip, review approval/rejection record. Current database command:
`pnpm run test:postgres`; the runner creates and removes its own cluster.

## Failure / rollback

Stop writes, preserve pending records, roll back the application and repair via
forward migration. Never delete committed business history.
