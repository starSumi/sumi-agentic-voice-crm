# C6 — release approval

**Gate owner:** release-owner
**Approvers:** commander, product, platform, security, operations

## Checklist

- [ ] C0–C5 evidence is complete, linked and independently reviewed.
- [ ] Unit, contract, integration, E2E, fault, load and security reports are green or explicitly waived.
- [ ] Normal, silence, no-source, low-confidence and TTS fallback records include IDs and timestamps.
- [ ] Staging smoke, migration compatibility and rollback drill pass on the release digest.
- [ ] `dist/BUILD-MANIFEST.json` binds every payload path, byte count and SHA-256 digest; clean rebuilds produce the same content-set digest.
- [ ] Runtime SPDX SBOM, dependency audit and secret scan are attached to the candidate; missing provenance is an explicit hold, never an implied pass.
- [ ] Release candidate workflow checks the exact reviewed `main` commit, package version and completed C6 before packaging.
- [ ] SLO dashboard, on-call, customer communication and incident process are ready.
- [ ] Final decision is recorded as `approved`, `held` or `rejected`.

## Required evidence

Signed release manifest, image digest, SBOM/provenance, migration range, test
bundle, approvals, canary result and rollback record. The candidate workflow is
manual and environment-gated; ordinary CI and the CI Operations Agent cannot
create a release, tag, publish, deploy or advance this checkpoint.

## Failure / rollback

Hold promotion or roll back the application image. Do not destructively roll
back committed database state.
