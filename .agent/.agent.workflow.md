# Supervisor workflow and delegation protocol

## Operating loop

```text
DISCOVER → CLASSIFY → PLAN → DELEGATE → EXECUTE → VERIFY → REVIEW → PROMOTE
                                  ↘ BLOCK / ESCALATE ↗
```

The Supervisor maintains one active phase and one active checkpoint. Parallel
work is allowed only when lanes have disjoint write paths or separate worktrees;
the final reconciliation is always serial under the Reviewer.

## Role topology

| Role | Accountability | May write | May approve |
| --- | --- | --- | --- |
| Commander | outcome, scope, priority and final handoff | orchestration state | none alone |
| Supervisor | phase execution, dependency graph and evidence completeness | `.agent*` state and assigned worktrees | phase readiness |
| Discover | source/runtime facts and unknowns | evidence scratch only | none |
| Delegate | task packet quality and routing | task queue/state | none |
| Worker | bounded implementation or test | assigned source paths | none |
| Reviewer | independent acceptance and drift check | review record | checkpoint recommendation |
| Specialist owners | domain correctness in their boundary | owned paths | domain sign-off |
| Product owner | customer outcome and acceptance | product evidence | business acceptance |
| Platform owner | identity, runtime substrate and deployment capability | platform/integration paths | platform sign-off |
| Operations owner | on-call, SLO, incident and rollback readiness | runbooks/ops evidence | operations sign-off |

## Mandatory delegation packet

```json
{
  "task_id": "T-000",
  "objective": "one measurable outcome",
  "role": "worker or specialist role id",
  "phase": "P2-domain-and-contract-hardening",
  "checkpoint": "C1",
  "source_basis": "commit or runtime observation",
  "read_paths": ["contracts/"],
  "write_paths": ["contracts/openapi.yaml"],
  "acceptance": ["pnpm run check", "named contract assertions"],
  "evidence_path": ".agent-artifacts/T-000/",
  "rollback": "revert one commit or restore one artifact",
  "deadline": "ISO-8601",
  "dependencies": []
}
```

No packet may use a broad repository write scope. A worker reports changed
paths, commands, failures, residual risks and a handoff summary. The Supervisor
re-runs the acceptance command; agent prose is never evidence by itself.

The phase-role matrix is the routing index. A task must name one accountable
role and may name multiple contributors only when their write paths are
disjoint. Product, platform and operations approvals are separate authorities;
they cannot be inferred from a specialist sign-off.

## Checkpoint transition rule

`planned → in_progress → completed` requires the card's exit criteria, evidence
links, named owner and rollback. `in_progress → blocked` requires the blocking
condition, three attempted alternatives or a documented external dependency,
and an escalation owner. A later checkpoint cannot close while an earlier one is
unresolved unless a time-bounded waiver is recorded.

## Evidence and audit

Use `source-confirmed`, `runtime-observed`, `inferred` or `unknown`. Store raw
logs and screenshots locally under `.agent-artifacts/`; redact secrets and PII
before promoting evidence into `docs/`. Every state change records ISO time,
actor, commit, command, result and next action.

## Session continuity

The versioned cursor is a reviewed handoff, not a live session database. At the
start of a new session, the Continuity Supervisor reads the manifest, state,
cursor and maintainer registry, then runs `pnpm run agent:resume`. That command
re-probes Git and writes the current thread snapshot outside the repository,
under `${CODEX_HOME}/operations/<repository>/<thread-id>/` when Codex identity
is available. A caller may select another external path explicitly.

The runtime snapshot records stable `open` or `closed` agent edges. It must not
claim that an old process is still running. Session transcripts, heartbeats,
PIDs, locks and retry cursors never enter Git. Before handoff, refresh the
versioned cursor only when a project fact, checkpoint or blocker changed; use
`pnpm run agent:snapshot` for generated operational evidence.

The CI Operations Agent runs only from trusted default-branch contexts. It may
publish a run artifact and reconcile one health Issue. It may not write source,
approve a pull request, change a checkpoint, or publish a release.
